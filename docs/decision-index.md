# Canonical Decision Index

Status: **Reconciled and implementation-ready, 2026-08-15**

This is a normative locator, not a competing specification. The repository has the pinned workspace, Core/lineage and operational-authority implementation, exact retained Counter and Agent Heist executors, both storage adapters, the public Python SDK, and the first-party UI. [`compatibility.toml`](../compatibility.toml) now has `release_ready = true` because its embedded implementation identities are complete; per ADR 0012, the still-detached cross-platform artifacts and acceptance reports must verify before that contract can support a distribution claim. When wording conflicts, use this authority order:

1. [`CONTEXT.md`](../CONTEXT.md) for whole-product domain language;
2. [Frozen Requirements](requirements.md) for normative behavior and scope;
3. [Wire Protocol](protocol.md) and [Activity Packs](activity-packs.md) for typed contracts;
4. [System Architecture](architecture.md) for logical persistence and runtime mapping;
5. [`compatibility.toml`](../compatibility.toml) and its canonical [`compatibility.json`](../compatibility.json) mirror for the machine-readable release contract;
6. [Extended Terminology](glossary.md) for supporting protocol, storage, and UI vocabulary.

## Cross-cutting evidence rules

- Canonical fixtures compare exact bytes, not decoded value equivalence.
- Failure fixtures distinguish `Faulted` from `Quarantined`, `room.sync_ack` from `observation.ack`, Activity Pack `Outcome` from Room Commit resolution, and pack-facing `due/new_due` from stored `scheduled_for`.
- Every JSON example and canonical JSON mirror must parse; the TOML/JSON compatibility pair must be semantically identical; every local Markdown link must resolve.
- A fixture or report is evidence only when its digest and exact implementation/engine/pack identities are recorded in the detached signed release manifest bound to a release-valid embedded compatibility contract.
