# IMO-54 retained Agent Heist compatibility

This lane closes the executable retained-revision compatibility gap inside the
Activity Pack seam and adds direct SQLite no-snapshot recovery evidence for the
broader IMO-54 criterion. Agent Heist now has two independently
keyed executable rows:

- `0.1.0` is the active revision and is selectable for new Rooms.
- `0.0.1` is retained-runnable but not selectable for new Rooms.

Replay and recovery resolve the stored `PackDigestV1` through the production
registry. Lookup is exact: a missing or tampered digest returns a typed failure
and never falls forward to the active revision. No kernel branch or server/
SQLite lifecycle change was made.

The offline UI parity fixture deliberately describes the current selectable
`0.1.0` revision (`blake3:b05a682f0923001914a800072ee68348e68b979453c93e033cba7916b99a4407`)
when replaying a retained Room. It no longer claims the orphan `755aa7…`
identity or labels a synthetic executor as retained-only; the actual retained-
only row remains `0.0.1` (`blake3:ee454c4d00357c70fcc9eeac5eb9782ef4317563d5eac24b59440c2e90bc595f`).
An executable Python test binds the parity fixture identity to the exact
selectable manifest row.

## Deterministic evidence

`examples/heist/retained_corpus.json` records the cross-platform Genesis/action
vector and both exact corpus/transcript identities. An executable `include_str!`
verifier parses that file, compares its full vector and identities with values
generated by the production registry, and rejects tampered or missing rows. The
core registry tests also construct the production registry, execute the
retained-only revision, replay its Genesis and transitions, and assert that the
active revision remains new-Room selectable while the retained revision is not.

The fail-closed tests cover:

- missing exact retained digest with no fallback;
- tampered stored Genesis bytes;
- tampered retained revision-lock bytes;
- exact retained Genesis preparation and replay through the production path.

The SQLite acceptance test
`imo54_heist_no_snapshot_recovery_covers_phase_view_attention_and_outcome_matrix`
drives real registered Agent Heist transitions through all six phases for the
current selectable digest and the retained non-selectable digest. It persists
the complete outcome/reason/score matrix, removes every paired snapshot and
disposable materialization, reopens, and recovers through the production
registry. Before and after recovery it compares immutable lineage, Complete
Head/Core/Activity/authoritative hashes, all corpus-authorized views and
projection hashes, observation/Attention bytes and hashes, activation rows,
timers/generations, frames/cursors/memberships, and final outcomes. Replay
asserts zero external effects and receipts. The pre-crash prefix evidence also
asserts the exact ordered phase set
`briefing -> negotiation -> commitment -> resolution -> result -> complete`,
with final reveal denied by the exact privacy-contract error before Complete
and available only at Complete. Canonical history remains unchanged and paired
snapshots are treated as disposable.
