# IMO-44/49/50 transaction-pooler evidence — Wave 6

Date: 2026-08-21

## Scope and evidence boundary

This report records a fresh, disposable PostgreSQL 17.11 plus PgBouncer
transaction-pool run for the IMO-44/49/50 criteria. It does not modify
Rust, Python, compatibility manifests, `release_ready`, or release evidence
rows. No credentials, DSNs, or temporary paths are recorded.

The PostgreSQL image was `postgres:17.11-alpine` at
`sha256:18cfe3ef5e6815560c98237d6216d1e5119702fb0f3894c8785dd58b8bbe5d73`.
The PgBouncer image was `edoburu/pgbouncer:latest` at
`sha256:4c1ca296ef525f108f5d3552cc337c0c09587cf8dae7f0067fd93349e47dc1cd`.
Both containers used a temporary Docker network and ephemeral loopback
ports. Authentication used a temporary static PgBouncer `auth_file` with
separate `admin` and `runtime` entries; no `auth_query` was configured.

## Non-promoted attempts and exact blockers

- A first setup passed URI-form DSNs to the Rust adapter. The adapter correctly
  rejected them with `remote PostgreSQL runtime connections require TLS`; this
  was a fixture-format error, not promoted evidence. The rerun used the
  adapter's supported keyword DSN form with `host=127.0.0.1`.
- A harness invocation after a standalone adapter invocation reused the same
  database and failed its deliberate fresh-create assertion because the
  operation was already durable (`assertion failed: !observations[0].duplicate`).
  It was discarded. The authoritative harness run above used a separate empty
  database and passed.
- A disposable setup initially relied only on `pg_isready`, which can report
  readiness before the configured database exists. That attempt returned
  `database "worldstream" does not exist` and was discarded; the final setup
  waited for a successful query against `worldstream`.

## Remaining boundary

This proves the PostgreSQL 17.11 direct-admin/runtime/transaction-pooler
provider lane and its normalized local conformance transcript. It does not
prove native Linux/Windows/OCI release artifacts, remote TLS connector
support, crash/power-loss recovery, or the other release rows. No release
manifest or compatibility readiness claim was changed.
