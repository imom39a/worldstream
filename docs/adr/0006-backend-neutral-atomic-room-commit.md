# ADR 0006: Use One Backend-Neutral Atomic Room Commit

Status: Accepted, 2026-08-15

## Context

SQLite and PostgreSQL have different physical locking and failure surfaces, while WorldStream needs one observable Room order, stable retries after lost replies, and an all-or-none bundle spanning canonical history, serving state, timers, private delivery, Activation decisions, and results. Treating actor order, a conditional update, or a successful driver call as the commit point would make crash and unknown-COMMIT behavior backend-dependent.

## Decision

WorldStream prepares one immutable, versioned `PreparedRoomWriteV1 = Create(PreparedRoomCreationV1) | Existing(PreparedRoomCommitV1)` outside storage locks. The storage port has exactly two operations: `commit(PreparedRoomWriteV1)` and `resolve(OperationIdentity, CanonicalRequestHash)`. Every invocation of either operation first acquires the same transaction-scoped Operation Identity serialization guard. The guard precedes every Room or generated-ID lock, so all paths share one deadlock-safe acquisition order.

The Existing branch binds an Operation Identity and Canonical Request Hash to the indivisible observed Complete Head `(room_id, room_seq, genesis_or_transition_hash, core_schema_version, pack_digest, core_state_hash, activity_state_hash, authoritative_state_hash)`, plus exact integrity generation, authority/capability, policy, and operation-specific input/timer witnesses. Its prepared intent is either one `Advance` or one `DurableDisposition { Rejection | NoChange }`. After taking the Operation Identity guard, its transaction takes the Room fence, rechecks identity and every witness, and persists the complete prepared bundle. An Advance atomically includes Transition/hash lineage, Complete Head, Core/Activity materializations, final Membership state, timer consumption/mutations, addressed Frames/frame heads, Activation decisions/intents/fences, and the applicable Semantic Receipt, including TimerFired. `NotApplicable` binds no identity, hash, or receipt. A disposition persists only its receipt and consumes no Room sequence.

The Create branch seals the administration Operation Identity/hash, exact creation-authority witness, selected exact pack revision, generated Room and initial Member IDs, seed and logical creation time, Genesis, initial Core/Activity State and timers, all three initial hashes, Complete Head zero, current materializations, initial operational Room Integrity State exactly `healthy` at generation `1`, and the `genesis_created` Semantic Receipt. It has no basis Head or pre-existing Room Integrity witness and does not use an existing-Room admission lane or Room fence. After taking the Operation Identity guard, its transaction resolves and fences the identity, rechecks creation authority and generated Room-ID absence, and atomically installs that complete bundle. Same identity/hash returns the original generated IDs and Head zero; changed hash is `Conflict`. A generated Room-ID collision returns `Reprepare` only after proving this write absent and permits resealing generated values under the unchanged identity/hash and caller-semantic input.

Durable database COMMIT is the sole linearization point for both branches. Pack initialization or reduction, projections, network publication, telemetry, derived indexing, and paired snapshot writes never occur while locks are held; snapshots and delivery are postcommit.

The storage seam exposes one Room Commit resolution algebra on both backends: resolved GenesisCreated/TransitionCommitted/RejectionRecorded/NoChangeRecorded with `New | Existing`, `NotApplicable`, `Reprepare`, `Fenced`, `Conflict`, `RetryableKnownAbsent`, `Indeterminate`, or `Fault`. `Outcome` is reserved for an Activity Pack domain result. Unknown COMMIT is resolved on the authoritative primary with the original identity/hash before retry, reprepare, scan, acknowledgement, or publication. While holding the same Operation Identity guard, `resolve` waits out every earlier same-identity writer and rereads the primary: `StoredResolution` returns the original branch-specific receipt, `Conflict` exposes another hash, and synchronized `KnownAbsent` is the proof that maps to `RetryableKnownAbsent`. A plain snapshot miss or inability to acquire the guard is `ResolutionUnavailable`, so it preserves `Indeterminate`. After synchronized `KnownAbsent`, a retained sealed plan may be retried identically. For creation only, if restart lost that plan, the server may freshly prepare generated Room/Member IDs, seed, logical creation time, and their derived bundle under the unchanged caller identity/hash, unchanged caller-semantic input and exact pack, and current authority; no Action or other operation may resample Semantic Time through this exception. A generated Room-ID collision remains an immediately proven-absent `Reprepare` under unchanged caller identity/hash.

## Considered options

- Relying on the in-memory Room actor alone was rejected because process failure and PostgreSQL concurrency outlive actor state.
- Retrying an ambiguous COMMIT as a new request was rejected because it can duplicate canonical work and change time-dependent input.
- Splitting receipts, timers, Frames, or Activation creation into later transactions was rejected because externally visible consequences could disagree with the accepted Transition.
- Writing snapshots inside the Room transaction was rejected because a replaceable cache would enlarge the correctness-critical lock and could roll back valid history.

## Consequences

SQLite routes both `commit` and `resolve` through its dedicated controlled writer and transaction-start reservation. PostgreSQL uses transaction-scoped Operation Identity exclusion for both operations—an xact-scoped advisory guard or equivalent unique-key guard that is safe under transaction pooling—then may commit different Rooms concurrently using a transaction-scoped Room-root row lock or equivalent guarded write under Read Committed with `synchronous_commit=on`. It has no global serialization, connection-affinity, or session-state correctness dependency. Both profiles must pass one failure-injection and transcript suite, including resolve racing an in-flight same-identity commit without a false `KnownAbsent`. Semantic Receipts or equivalent tombstones remain resolvable with Room lineage, including after archive. The cost is deliberate per-Room and per-identity serialization and potentially duplicated prepared work when a witness changes, in exchange for portable crash semantics and no blind retry.
