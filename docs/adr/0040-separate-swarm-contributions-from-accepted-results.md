# Separate Swarm contributions from accepted results

Agent Participants may propose and claim Swarm Work Items, each with one
accountable owner. Participants share coordination facts through WorldStream
and submit separate, attributed Swarm Contributions for explicit integration
into a result. This supports coding and non-coding goals while avoiding a
requirement that independent agents concurrently mutate one shared deliverable.
It adds integration and review work, but preserves attribution and makes
conflicting contributions visible before acceptance.

Artifact handling depends on the task: code changes may use patches or Git
worktrees, writing may use drafts or sections, and analysis may use findings
and calculation evidence. Git is not a universal prerequisite. Recording a
contribution, integrating it, and accepting a goal result remain distinct.
Automatic completion requires the agreed goal-specific checks and review by
at least one different Agent Participant from the existing roster. A one-agent
Swarm requires human review. Integration is a claimable Work Item with one
temporary owner; its resulting deliverable is reviewed against the applicable
inputs and criteria. Relevant changes require renewed validation of affected
material. Unresolved blocking review findings prevent acceptance; a later
passing review does not erase them. Another eligible roster member can examine
a dispute, with unresolved disagreement surfaced to the human.

Each Swarm has an approved working area with separate contributions and a
clear result location. Integration may update original resources within the
goal's existing authorization. Handling concurrent resource changes and changes
after completion preserves result provenance: keep newer shared resources,
refresh or reconcile affected contributions, and repeat affected checks and
review. Unresolved conflicts block affected work and dependents while
independent work continues; integration does not silently overwrite newer work.

Completion preserves one accepted result against its identified inputs and
criteria and stops automatic agent work. Later information or contributions do
not silently change that result. Explicit reopening assesses changed inputs
and produces a newly reviewed result version in the same Room.
