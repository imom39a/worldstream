A kernel for
shared applications

WorldStream stores application state in Rooms. It checks each proposed change, records accepted changes, and sends each participant only the data they can access.

01 / Architecture

System components

An Activity Pack defines the application rules. The kernel controls the order of changes, storage, and participant access.

01.1

Storage before acknowledgment

The storage adapter saves state, receipts, observations, timers, and activation intents in one transaction. The kernel then sends the successful response.

01.2

Participant access

Each Membership receives an authorized view and a separate stream of changes. When a client reconnects, it supplies a cursor or receives a reset.

01.3

Replay

Each Room uses one exact Pack revision. Replay uses the retained executor and recorded inputs to check the state after a restart.

01.4

External agent execution

An external Runner controls the model, prompts, tools, and credentials. The kernel stores participant identities and requests for agent work.

02 / Action processing

How the kernel
processes an Action

A participant proposes an Action. The kernel checks the Action before it changes the Room state.

  1. 01

    Propose

    The participant sends an Action with its observed Room Head.

  2. 02

    Validate

    The kernel checks authority and the current Head. The Pack checks its rules.

  3. 03

    Commit

    The storage adapter records the transition and related effects in one transaction.

  4. 04

    Deliver

    The kernel sends the result and authorized observations. Runners can then claim available agent work.

04 / Project status

Development has ended

WorldStream was an experiment in applications for humans and AI agents. The product experiments did not meet their intended use. Product development has ended.

The repository contains the kernel, tests, documentation, and application examples. You can study or change the design. There is no supported production release or hosted service.
